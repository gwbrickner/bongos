# M3.1: ACPI tables
**Branch:** `m3-1-acpi-tables` · **Started:** 2026-10-01 · **State:** done

## Summary
The kernel now finds, validates and keeps the ACPI tables. It copies every valid table out of firmware memory
(RSDP, XSDT with an RSDT fallback, their entries, and the FADT's DSDT) through temporary read-only KVA windows, so it
works on BIOS (SeaBIOS keeps everything in RESERVED memory the HHDM does not map) as well as UEFI, and parses the
FADT, MADT, MCFG, HPET and IVRS into kernel structs with strict bounds, checksum and overflow checks. The boot log
lists the MADT CPUs, I/O APICs, overrides and the MCFG base, and ACPI_RECLAIM is freed (zeroed) only after every table
is a kernel copy (never ACPI_NVS). `acpidump=1` dumps the tables on serial (`docs/specs/acpidump.md`); the new host
tool `tools/acpiextract` turns that log into files and checks it, and QEMU's q35 tables (UEFI and BIOS) are stored in
`tests/data/acpi/qemu-q35/`. The pure loader and parsers are host-tested against them, with fuzzers (D-166..D-170).

## Plan
Design by `architect` (consulted 2026-10-01). Decisions: D-166..D-169. Spec: `docs/specs/acpidump.md`.

Core ideas: a pure, host-tested parser core (`kernel/drivers/acpi/acpi-tables.c`) that reads firmware
memory only through an `AcpiPhysOps` callback; the kernel glue (`acpi.c`) reads through temporary
read-only WB KVA mappings (the HHDM does not map RESERVED memory, where BIOS puts the RSDP and every
table), copies every accepted table into kmalloc/vmalloc memory, and keeps the copies. Only after
`acpiInit` succeeds does `pmmReclaimAcpiMemory()` free the recorded ACPI_RECLAIM ranges.
