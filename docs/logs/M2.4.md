## Plan
ROADMAP M2.4 steps: (1) slab caches with constructors and per-CPU magazines; `kmalloc` size
classes 16-8192 bytes; (2) `vmalloc` for large, page-granular allocations with guard pages, built
on M2.3's `vmmMapKernel`/`vmmUnmapKernel` and KVA allocator (`kernel/mm/vmm.c`/`kva.c`); (3)
debug-build poisoning, redzones, and double-free/use-after-free detection; (4) ktests for stress,
alignment, redzone overflow, and a guard-page fault. Needs: M2.3 (done).

Sub-steps:
1. Consult the `architect` subagent for the design: slab cache/magazine layout, size-class table,
   `Page.privateWord` usage (reserved for this per page.h), the debug poison/redzone/double-free
   scheme and its relationship to D-082's `archTrapCatch`/`TRAP_CATCH_KERNEL_BUG`, and the
   kmalloc/vmalloc header API shape. Record as D-092+.
2. Implement the slab allocator core (cache create/alloc/free, per-CPU magazines -- BSP-only for
   now per M2.2's precedent, real per-CPU arrives M3.5).
3. Implement `kmalloc`/`kfree` on top of it (fixed size classes 16..8192).
4. Implement `vmalloc`/`vfree` on top of `vmmKvaAlloc`/`vmmMapKernel` (guard pages already built
   into `vmmKvaAlloc`).
5. Debug-build (`KERNEL_DEBUG`) poisoning/redzones/double-free/UAF detection, wired through
   `panicBug()`/`archTrapCatch` the way pmm's D-082 does.
6. ktests: stress, alignment guarantees, redzone-overflow detection, guard-page fault. Host tests
   for any pure logic (size-class math, free-list bookkeeping) that doesn't need real paging/pmm.
7. `qemu-tester`: `make test`/`make test-full`, `make host-tests`, `make format-check`.
8. `reviewer` pass(es); fix Critical/Should-fix.
9. Update ROADMAP.md/STATUS.md, write Summary, open PR (`needs-owner: yes`).
