## Plan
Roadmap steps (ROADMAP.md M1.4):
1. Loader: GOP mode selection (ARCHITECTURE §5.5 step 5, plus a `resolution=` override), fill
   `BootInfo.fb`.
2. Kernel `fbcon`: an 8x16 bitmap font (`data/fonts/console.psf`), scrolling and colors, mirrors
   klog.
3. Full `boot.cfg` parser with `[entry]` sections, `timeout`, and `default`. Menu on screen and
   serial (arrow keys + Enter; on serial, number keys).
4. Harness: QEMU `screendump` at the boot menu and after the kernel banner, compared with
   `tools/imgdiff` (introduced here) against reference PNGs.

Design questions to run past the `architect` subagent before implementing (on-disk format +
boot-handoff-adjacent, per CLAUDE.md): the exact `[entry]`-section boot.cfg schema (ARCHITECTURE
§5.2 lists the keys and the three default entries but not per-entry vs. global scoping, or the
`default`/`timeout` key semantics precisely), how the PSF font is embedded and consumed, and the
screenshot-test comparison approach (`tools/imgdiff` threshold/format).

### 2026-09-25 02:40: Step 2 done -- original console font (D-069)
- **Changed:** `data/fonts/console.txt` (new: the source of truth, a '#'/'.' 8x16 grid per glyph
  for the replacement glyph (0x00) plus every printable ASCII character 0x20-0x7E -- 96 glyphs
  total); `data/fonts/console.psf` (new: the compiled PSF2 binary, 2080 bytes); `tools/mkfont/
  main.c` (new: `mkfont psf SRC.txt OUT.psf` parses and strictly validates console.txt and emits
  the PSF2 binary; `mkfont c SYMBOL IN.psf OUT.c` validates a PSF2 file's header and emits a C
  array + length, for linking the font directly into the loader/kernel image); `mk/font.mk` (new:
  builds `tools/mkfont`, `make font` regenerates `console.psf` in place, `make font-check`
  regenerates into `build/` and `cmp`s against the checked-in file, and a reusable rule for
  `build/gen/console-font.c`); `Makefile` (includes `mk/font.mk`); `mk/format.mk` (`format-check`
  now depends on `font-check`, so a stale/hand-edited `console.psf` fails CI the same way
  misformatted C does); `boot/common/include/console-font.h` (new: the PSF2 constants, a
  `Psf2Header` struct, and `extern` declarations for `fontConsolePsf`/`fontConsolePsfSize` --
  shared between the loader and kernel like `bootinfo.h`, so no BootInfo field is needed).
- **Why:** ROADMAP M1.4 step 2 needs an "original or public domain" 8x16 font; D-069 picked
  original (data/fonts/README.md said OFL, ROADMAP said original-or-public-domain -- the docs
  disagreed, resolved in favor of original to avoid any OFL license-accompaniment question inside
  the shipped `BOOTX64.EFI`/`kernel.elf`). The font itself was authored with a small procedural
  stroke generator (horizontal/vertical/diagonal line primitives, run as a one-off scratch script,
  not checked into the repo -- only its output, `console.txt`, is) rather than by tracing any
  existing font's bitmap data glyph-by-glyph, per D-069's "must not trace existing fonts" rule.
  Kept `console.txt` itself as the single source of truth per the architect's design, with
  `tools/mkfont` doing strict validation (row/column counts, required glyph range, duplicate/
  out-of-range indices) so a malformed edit fails loudly rather than silently shipping a corrupt
  glyph.
- **Simplification worth flagging:** the font is legible but simple (straight strokes only, no
  curves) -- one known ambiguity is that digit `5` and letter `S` render as literally the same
  bitmap (both are the classic top/upper-left/middle/lower-right/bottom seven-segment shape).
  Acceptable for a v1 debug/boot console; a later milestone (or the owner) can refine individual
  glyphs in `console.txt` without touching any of the surrounding tooling -- `tools/mkfont`
  re-validates and regenerates `console.psf` from it either way.
- **Tests:** `make font` produces a 2080-byte PSF2 file (verified: magic `0x864AB572` little-
