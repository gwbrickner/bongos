## Plan
Roadmap steps (ROADMAP.md M1.4):
1. Loader: GOP mode selection (ARCHITECTURE §5.5 step 5, plus a `resolution=` override), fill
   `BootInfo.fb`.
2. Kernel `fbcon`: an 8x16 bitmap font (`data/fonts/console.psf`), scrolling and colors, mirrors
   klog.
3. Full `boot.cfg` parser with `[entry]` sections, `timeout`, and `default`. Menu on screen and
   serial (arrow keys + Enter; on serial, number keys).
4. Harness: QEMU `screendump` at the boot menu and after the kernel banner, compared with
   `tools/imgdiff` (introduced here) against reference PNGs.

Design questions to run past the `architect` subagent before implementing (on-disk format +
boot-handoff-adjacent, per CLAUDE.md): the exact `[entry]`-section boot.cfg schema (ARCHITECTURE
§5.2 lists the keys and the three default entries but not per-entry vs. global scoping, or the
`default`/`timeout` key semantics precisely), how the PSF font is embedded and consumed, and the
screenshot-test comparison approach (`tools/imgdiff` threshold/format).

### 2026-09-25 01:10: Architect design received; docs updated (D-067 through D-070)
- **Changed:** `docs/DECISIONS.md` (D-067 boot.cfg grammar, D-068 GOP mode selection + framebuffer
  HHDM mapping, D-069 original console font, D-070 screenshot-test approach), `docs/ARCHITECTURE.md`
  §5.2 (full boot.cfg grammar), §5.3 (`pitch` is bytes), §5.4 (framebuffer HHDM mapping bullet),
  §5.5 (GOP-before-menu ordering, GOP mode-selection rule), `data/fonts/README.md` (original font,
  not OFL).
- **Why:** the `architect` subagent flagged a real blocker the roadmap steps didn't call out: the
  GOP framebuffer is MMIO, and D-059/§5.4 say MMIO is never HHDM-mapped, so `fbcon`'s first pixel
  write would fault under the loader's page tables as they stand today (M2.3, which owns the
  kernel's real paging, is milestones away). D-068 fixes this with a narrow, explicit exception: a
  4 KiB-page, UC-, NX, global mapping of just the framebuffer range, verified by a self-check and
  recorded as a `BOOT_MEM_FRAMEBUFFER` overlay -- superseding D-059 for that one range only.
  D-067 gives boot.cfg's `[entry]` sections an exact grammar (scoping/inheritance, `default`/
  `timeout` semantics, a 9-entry cap for single-keystroke serial selection) with a two-phase
  zero-copy-then-resolve struct design that stays small enough for M2.5's BIOS stage2 later.
  D-069 picks an original 8x16 font over an OFL one (ROADMAP says "original or public domain";
  `data/fonts/README.md` said OFL; the docs disagreed -- resolved in favor of original, avoiding
  license-accompaniment questions inside the shipped binaries). D-070 nails down non-flaky
  screenshot sync points (`loader: menu ready`, a `SCREENSHOT kernel` + ack handshake) instead of
  capturing on a wall-clock timer, plus a from-scratch PPM/PNG codec for `tools/imgdiff` (no
  third-party image libraries, per ARCHITECTURE §0). Full design (grammar, structs, algorithms,
  file layout) is in the architect's report, referenced here rather than duplicated; see the
  design rationale embedded in each D-0xx entry above for the compressed version.
