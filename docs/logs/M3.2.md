# M3.2: Interrupt controllers
**Branch:** `claude/nifty-bell-wrb444` (session-designated; the CLAUDE.md name would be `m3-2-interrupt-controllers`) · **Started:** 2026-10-01 · **State:** done (awaiting owner merge; no PR opened yet)

## Summary
The kernel now owns its interrupt controllers and runs with interrupts enabled. The 8259 pair is remapped to
0x20/0x28 and fully masked; the local APIC comes up in x2APIC mode when CPUID allows it (else xAPIC through a new UC
MMIO mapping, `vmmMapMmio`) with all LVTs masked except the MADT's NMI pin; the IOAPICs are mapped, every pin masked,
and ISA IRQs are routed through the MADT interrupt source overrides with their polarity and trigger. `irq.h` adds a
vector allocator (48-239), `irqRegister`, route/mask/unmask, and a dispatcher with the EOI after the handler, a
no-EOI spurious vector, 8259 spurious-IRQ checks and a log-count-EOI path for unregistered vectors. `kernelMain`
runs `sti` after `irqInit()`, so ktests run with IF=1; klog is IRQ-safe and `archTrapCatch` refuses to catch faults in
handlers. 22 irq/MMIO ktests (self-IPI, spurious, unhandled, IOAPIC routing of the PIT on ISA IRQ 0) pass on UEFI and
BIOS. D-171..D-175.

## Plan
Design by `architect` (consulted 2026-10-01). Decisions to record: D-171..D-175. Key points: a UC mapping
type + `vmmMapMmio` (D-171); 8259 remap+mask, LAPIC (x2APIC when CPUID allows, else xAPIC MMIO), IOAPIC
bring-up (D-172); IF=1 from `kernelMain` after `irqInit()`, vectors >= 32 go to `irqDispatch` (handler, then
LAPIC EOI; 0xFF counted without EOI; 39/47 checked against the 8259 ISR; unregistered vectors logged once,
counted, EOI'd, never a panic), handlers run IF=0 with no allocation, klog made IRQ-safe, `archTrapCatch`
refuses in IRQ context (D-173); vector bitmap allocator + `irq.h` API (D-174); ktest strategy (D-175).
Pure code (vector map, RTE encoding, ISO resolution, GSI lookup) lives in
`kernel/arch/x86_64/irq-core.c` and is host-tested.
