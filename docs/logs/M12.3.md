## Plan
Design comes from the `architect` consult (2026-09-30). Key points:
- The font engine lives in **libs/gfx** (ARCHITECTURE §2 says so), new files `gfx-font.h`,
  `gfx-text.h`, `font-*.c`, `text-*.c`. `$(wildcard libs/gfx/*.c)` already builds them, so no mk
  edit. Prefixes `gfxFont*`, `gfxGlyph*`, `gfxText*`, `gfxUtf8*`.
- `GfxFont` is zero-copy over caller bytes (TrueType glyf only: cmap 4/12, loca, glyf incl.
  composites, hmtx, kern format 0, GPOS PairPos kerning). No hinting (D-153). Untrusted input:
  every read bounds-checked, hard limits.
- Rasterization reuses libs/gfx exact-area AA (`gfxFillPathMask`), 4 subpixel bins, layout in
  26.6 fixed point. Glyph cache = LRU by bytes. Fallback chain <= 8 faces. UTF-8 with maximal
  subpart U+FFFD; simplified UAX #14 line breaking.
- Data: Liberation Sans + Mono Regular 2.1.5 (OFL 1.1), byte-identical, with license.
- Decision numbers D-150.. (D-120..D-139 are the M2.6 lane's, D-140..147 are M12.2's).
- Status codes: only existing ones (OK/INVALID/NOT_FOUND/NO_MEMORY/UNSUPPORTED). Not touching
  `uapi/status.h`.

Owner questions (parallel lane, so recorded here and not in STATUS.md):
1. Liberation Sans and Mono **Regular only** (about 730 KB) as the UI and monospace fonts. Ship
   Bold/Italic now or with M12.5? The engine has no synthetic bold/oblique.
2. Unhinted, non-gamma-corrected AA looks softer on 1x displays. Acceptable, rather than a
   TrueType bytecode interpreter later (large attack surface)?
3. Add full UAX #14, grapheme clusters and GDEF mark positioning to ROADMAP M16.3's text?
4. D-153 extends D-142's float-file list to `font-glyf.c` and `font-render.c`.
