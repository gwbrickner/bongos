## Plan
Roadmap steps (ROADMAP.md M2.1, needs M1.3 which is merged):
1. Kernel GDT (§7.1 layout) + TSS with IST1-3. IDT with all 32 exception stubs. The handler
   prints the vector, error code, registers, CR2, and a symbolized backtrace.
2. Embed a compressed kernel symbol table in the image (post-link step) and add `symbolize()`.
3. Stack protector runtime (`__stack_chk_guard` seeded from `BootInfo.randomSeed`), plus the
   UBSan runtime with our own handlers (debug builds).
4. ktests: `int3` resumes; a deliberate #PF is reported with the correct CR2; a deliberate #UD is
   caught; a stack smash is detected.

**Done when:** those ktests pass, and panic output includes a symbolized backtrace.

Consulted the `architect` subagent first (interrupts/exceptions/the boot handoff are all on
CLAUDE.md's consult-first list) for: the exact GDT/TSS/IDT layout and IST stack allocation (no
real memory allocator exists until M2.2/M2.4, so this is BSP-only and statically allocated for
now -- SMP bring-up is M3.5, much later); a macro-generated exception-stub table instead of 32
hand-written near-duplicates; the C-level TrapFrame/handler design; how "compressed kernel symbol
table" should work without any third-party code (post-link extraction + a from-scratch encoding,
matching the `tools/mkfont`/`tools/imgdiff` precedent of from-scratch host tooling); which
`__ubsan_handle_*` entry points are actually needed; and -- the trickiest part -- how a ktest can
deliberately trigger #PF/#UD/a stack smash and have the handler recognize "this was an expected
test fault" and report ktest PASS/FAIL then continue running the *next* ktest, rather than
panicking the whole kernel (matching "int3 resumes").

### 2026-09-25 (architect design received): D-072 through D-078, ARCHITECTURE updated
- **Changed:** `docs/DECISIONS.md` (D-072 through D-078), `docs/ARCHITECTURE.md` (§3's UBSan
  check list, §6.6's stack-canary wording -- supersedes the old "seeded from the CSPRNG" text,
  §7.1/§7.2's full GDT/TSS/IDT/IST design and BSP-only caveat through M3.4, §23's
  `archTrapCatch` ktest-fault mechanism, §24's KSYM v1 pointer), `docs/ROADMAP.md` (M2.1 heading
  now carries `needs-owner`, per D-045/§25's "interrupts or SMP" rule -- the architect caught
  that the original heading was missing it).
- **Why:** the architect's design (full transcript in the subagent hand-back) corrected several
  assumptions from my brief before I'd written any code:
  1. #BP (int3) must **not** advance RIP -- it's a trap, not a fault; the saved RIP already
     points past the `int3` byte. Resuming is a plain `iretq`.
  2. `no_stack_protector` alone does **not** make the canary reseed safe -- clang 18 can inline
     a `no_stack_protector` function into a protected caller, confirmed by a direct compiler
     probe. The reseed function needs `noinline` too, called from a `no_stack_protector`
     `kernelMain`.
  3. The bare `-fsanitize=undefined` group is unsafe here -- clang 18 folds in `function` for C,
     which prefixes every function with a type-hash read on indirect calls; hand-written asm
     entry points (like `kernelEntry`) carry no such prefix, so an indirect call into one would
     read unmapped memory. Need the explicit check list from D-076 instead.
  4. D-061's "exactly four `PT_LOAD`s" needs superseding (D-073): the three IST stacks each need
     their own `PT_LOAD` (a guard page is a gap *between* segments, so one shared PT_LOAD can't
     hold three guarded stacks). `ELF_MAX_SEGMENTS`=8 already has room (7 total).
  5. LIDT must come after LTR (an IST gate taken before TR is valid reads IST from garbage and
     triple-faults).
  Full design covers: GDT/TSS exact layout and selectors (D-072); `%rep`-generated IDT stubs for
  all 256 vectors into a 176-byte TrapFrame, with a correct per-vector error-code-push table
  (D-074); the C-level `trapDispatch` reading CR2 first, panic-vs-resume policy per vector; a
  from-scratch "KSYM v1" compressed symbol table format with a two-pass-link-plus-verify build
  (`tools/ksyms`, matching the `tools/mkfont`/`tools/imgdiff` from-scratch-host-tool precedent,
  D-075); the UBSan handler ABI/data structures and panic policy (D-076); the exact stack-canary
  derivation and reseed placement (D-077); and `archTrapCatch`, a setjmp/longjmp-style
  register-context save/resume so a ktest can deliberately trigger #PF/#UD/a stack smash and
  have the handler recover control instead of panicking the whole kernel (D-078). Detailed file
  list, ktest plan, and failure-mode diagnostics table also provided -- see the subagent
  transcript for the full spec; I'll reference specific pieces of it in each implementation
  step's log entry rather than repeating the whole thing here.
