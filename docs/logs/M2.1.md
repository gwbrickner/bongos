## Plan
_Break the roadmap steps into concrete sub-steps. Note which subagents you'll consult._

ROADMAP.md's M2.1 steps:
1. Kernel GDT (ARCHITECTURE §7.1 layout) + TSS with IST1-3. IDT with all 32 exception stubs.
   The handler prints the vector, error code, registers, CR2, and a symbolized backtrace.
2. Embed a compressed kernel symbol table in the image (post-link step) and add `symbolize()`.
3. Stack protector runtime reseeded from `BootInfo.randomSeed` (already stubbed in
   `kernel/core/stack-protector.c` with a fixed compile-time canary), plus a UBSan runtime with
   our own handlers (debug builds).
4. ktests: `int3` resumes; a deliberate #PF is reported with the correct CR2; a deliberate #UD
   is caught; a stack smash is detected.

**Done when:** those ktests pass, and panic output includes a symbolized backtrace.

Consulting the `architect` subagent first (interrupts/exceptions are on CLAUDE.md's
consult-first list) for: the real GDT/TSS layout given this is currently BSP-only (no
per-CPU/SMP until M3.5), IST stack sizing, the IDT gate layout + a shared assembly stub design
instead of 32 near-duplicates, the exception-frame/backtrace design given `entry.asm` zeroes
`rbp` and no `-fomit-frame-pointer`, the symbol-table embedding format/tool, sequencing of the
stack-protector reseed relative to IDT install, a minimal UBSan runtime, and concrete ktest
designs for the four required tests (including how to trigger+recover from #PF/#UD/int3/stack
smash without wedging the boot).
