### BUG-M3.4-1: the validator ktests passed against a broken validator
- **Severity:** S2 · **Subsystem:** other (lock validator tests)
- **Commit found at:** b9bc7e8 · **Profile:** debug · **Config:** `tests/harness/run-matrix.sh <uefi 1> --image build/bongos-ktest.img` + `make _check-ktest-pass`
- **What happened / expected:** with `lockdepCoreCheckRelease`'s "IRQs enabled while held" branch disabled, or its
  NOT_HELD branch disabled, every M3.4 ktest and `mk/test.mk` check still passed; a broken check must fail `make test`.
- **Repro:** mutations `relchk` (`if (0 && h->irqCtx == 0 && h->irqsOn == 0 && irqsOn && ...)`) and `nothel`
  (`if (0 && idx < 0)`) in `kernel/sync/lockdep-core.c`.
- **Evidence:** with the new tests present, the only failures were `KTEST FAIL
  lockdep_irqs_enabled_while_held_reported: ... reports == 1 (0x0 != 0x1)` and `KTEST FAIL lockdep_not_held_reported:
  panic: UBSAN: array index out of bounds at kernel/sync/lockdep-core.c:257:29`; every original test passed.
- **Root cause:** the suite exercised only the acquire-time checks; neither release-time report had a ktest.
- **Fix:** eabf7b4 · **Regression test:** `lockdep_irqs_enabled_while_held_reported`, `lockdep_not_held_reported`
  (both required in `mk/test.mk`).

Suspicions checked and dropped:
- **Panic while holding klog's lock.** A temporary ktest took klogLock and wrote to address 8: the full `PANIC:
  exception #PF` report printed through the bypass and the run ended `KTEST FAIL` (no hang). NMI and every other
  vector go through the same `trapReportAndPanic` -> `panicEnter` path, and UBSan/stack-protector call `panic()`
  directly, so all of them reach the bypass before printing.
- **A report raised while releasing klogLock.** The raw release runs before `lockdepRelease`, so the report's own
  `klogRaw` finds the lock free. A report raised while acquiring any lock runs before the spin, so klogLock is never
  held by the reporting context except through the re-entry of finding 2.
- **A longjmp out of the validator** (a fault or UBSan trip with graphLock held and `lockdepRecursion` set): every
  path into `lockdepAcquire/Release` raised `preemptCount` first, so `archTrapCatch`'s balance check panics instead of
  silently stranding graphLock.
- **Ticket wrap-around** at 0xFFFFFFFF for `spinLock`, `spinTryLock`, `spinUnlock` and the unlock-of-unlocked check
  (`spin_ticket_wraparound`, both profiles).
- **IRQ-context segments.** A handler's lock taken while the interrupted code holds another records no edge, and the
  reverse order later is not an inversion (`lockdep_irq_segment_records_no_edge`); the held depth is unchanged across
  the IRQ. Out-of-order release keeps the rest of the stack (`lockdep_out_of_order_release`).
- **Trylock.** A trylock of a second lock of a held class is allowed; a trylock with IRQs on still marks the class
  IRQ-unsafe and a later use in a handler is reported (`lockdep_trylock_*`).
- **Slab drop/retake under the validator.** `slabRefillLocked`/`slabReclaimEmptyLocked` release and retake slabLock
  around pmm calls; 64 x 2 KiB kmalloc/kfree plus vmalloc/vfree record no `pmm -> vmm`, `pmm -> slab`, or
  `klog -> *` dependency (`lockdep_kernel_lock_order`), and no locked section calls `panicBug` (every `slabBug`,
  `pmmBug`, `vmallocBug` and vmm `panicBug` is reached with the lock already dropped).
- **Held-depth overflow, table-full, edge-full.** Host-tested (`lockdepHeldOverflowAndEdgeFull`,
  `lockdepClassTableFull`); in the kernel, a full table logs `[error] lockdep:` and `enabled=0`, both of which
  `make test` rejects.
- **preempt underflow** is caught as a kernel bug and leaves the count at 0 (`preempt_count_balance`).
- **Stored traces.** Each edge trace starts at `lockdepCoreCommitAcquire` and reaches the acquiring caller and test
  within the 10 frames (seen in every report). Cosmetic only: the stored traces print before the `kaslr slide` header,
  which appears only on the current stack.
