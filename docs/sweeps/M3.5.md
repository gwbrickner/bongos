### Analyzer triage
Baseline on main (docs/STATUS.md): 5 warnings. Now 6 (after f9c8270):
- `kernel/include/list.h:50` x2 (from kernel/mm/pmm.c via pmmDrainCacheLocked/listPopHead, and from
  kernel/mm/slab.c via slabReclaimEmptyLocked/listRemove): **false positive**, both. The analyzer
  assumes the list head's `next` still points at the node just removed; listRemove() relinks
  `node->prev->next` (the head itself for the first node), which it does not track through the alias.
  The slab.c instance is new in this milestone (present at 3ae3ee1, before this run's slab fix).
- `kernel/test/kmalloc_test.c:68,143,365`, `kernel/test/pmm_test.c:405`: pre-existing, untouched
  test files (leads only).
- `kernel/arch/x86_64/smp-x86.c:612` "Potential leak of memory pointed to by 'pmmBlob'": **real**
  (finding 9), fixed f9c8270.
