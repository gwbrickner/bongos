- `acpiReadPhys` `pageEnd = (phys+len+0xFFF)&~0xFFF` wrap: needs `phys+len > 2^64-0x1000`, which requires a map region
  ending there; validated regions are page-aligned and end <= 2^64-0x1000, and below 1 MiB it cannot wrap.
- Page granularity vs the byte-granular policy: map regions are page-aligned (validated) and 1 MiB is page-aligned,
  so every page mapped for an allowed byte range lies in allowed memory.
- vmmMapKernel failure partway (cache conflict, MAXPHYADDR, table OOM): it validates all pages before writing and
  rolls back on OOM; `acpiReadPhys` then frees the KVA. Proven by `acpi_read_phys_refuses_bad_ranges`.
- kmalloc/vmalloc pairing at KMALLOC_MAX_SIZE: alloc and free decide on the same `len`, and every free site passes
  the length it allocated (`loadOne`, `acpiTablesFree`). Proven at 8191/8192/8193 by `acpi_alloc_free_boundary`;
  QEMU's DSDT (8390 bytes) takes the vmalloc path on both firmwares.
- Parser OOB on hostile lengths (MADT/MCFG/HPET/IVRS/FADT): every field read is inside the checked entry/table
  length; fuzzed under ASan over every length 0..600 (`acpiParsersSurviveRandomBodies`). UBSan alignment: all
  reads are byte-wise.
- Loader failure paths: every NO_MEMORY return goes through `failLoad`; fuzzed with random allocation failures
  (`acpiLoadSurvivesRandomMemory`, live-allocation count back to 0 on every path).
- acpiextract: path names come only from sanitized SIG4 (`[A-Za-z0-9_]`, enforced by `verifyTable`); corrupted
  dumps fuzzed under ASan/LSan (`acpiExtractSurvivesCorruption`).
- Vacuous ktests: on UEFI every table is page-aligned, so the original six ktests *passed* with `acpiReadPhys`'s
