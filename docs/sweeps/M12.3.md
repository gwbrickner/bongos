Leads (not bugs, or outside the diff):
- L1 (S4, gfx-font.h:13): "an outline is at most ~164 KB" is the steady state. While growing,
  `outlineReserve` holds the old and new arrays at once (peak ~238 KB, which
  `glyfAdvLimitsAreExact` pins). Suggest rewording to "~164 KB (~240 KB while growing)".
- L2 (design, D-153): `SCALED_COMPONENT_OFFSET` transforms the offset by the full 2x2 matrix
  (rotation too). FreeType scales each axis by the column norm instead. D-153 doesn't say which,
  the shipped fonts don't use the flag, and the tests pin the current choice.
- L3 (pre-existing D-142 pattern, outside the diff): gcc ignores `#pragma STDC FP_CONTRACT OFF`.
  Determinism then rests on gcc's `-std=c17` default of `-ffp-contract=off`, or on building with
  clang. If libs/gfx is ever built with gcc in a GNU mode for an FMA target, add
  `-ffp-contract=off` to its flags.
- 90d8650's message says the new tests kill "25" kerning mutants. The measured number is 26
  (finding 1).

Specifically checked and proven safe (reading, then the tests and fuzzing above):
- Every `d[q]` raw read in `loadSimple` is guarded by `q < end`, and every multi-byte read uses
  `fontFits`. Flags repeat into `onCurve` only after `rep <= nPts - i`.
- Point and contour totals are checked against the limits before `outlineReserve`, so the
  doubling can't exceed the caps.
- Composite work is bounded (depth 8, 256 components in total, points capped). A cycle ends at
  the depth limit.
- Coordinates accumulate in int32. The worst case is 16384 x 32767, which can't overflow.
- Float magnitudes stay below ~1e12, so NaN or inf can't come from font data. The renderer's
  bbox skips a NaN only after the first point, which is unreachable because the render transform
  is finite.
- The renderer's `floorI`/`ceilI` are exact within +-2^24. The mask is at most 2048x2048, and
  the translated outline stays in [0, w] x [0, h] because float rounding is monotone.
- Every GPOS/kern offset sum is uint64 and bounded by the table end. The extension offset32 is
  validated before it's stored as uint32. `kernSubLookup` holds at most 32. The sum over at most
  32 lookups of int16 values can't overflow.
- Every binary search is `lo + (hi - lo) / 2` over a count validated with `fontFits`, so
  unsorted data terminates.
- On every failure path the image is zeroed and the mask freed. The strict allocator checks free
  sizes, foreign frees and leaks across all the allocation-failure sweeps.
